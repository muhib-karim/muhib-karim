# muhib-karim

AI engineer · Software verification & validation · Australia

I came to software through automotive test engineering, so I build tools the way I was trained to test: written requirements, repeatable checks and evidence someone else can inspect. Most of my recent work is in AI evaluation, API verification, LLM training data and offline voice input.

## Data engineering for LLM training

Five repos, one per stage of a training-data pipeline. Each is built to the same rule: every published number is regenerated by a script from committed raw logs, and each README lists its honest gaps. All five are in progress, and all ran on a shared 4-vCPU, 8 GB, CPU-only machine.

```
crawl-foundry  ->  dedup-scale  ->  agent-pipeline-qc  ->  countrykit-bangla  ->  tiny-tune + agent-eval-harness
   crawl          near-dedup +      generate, critique,     SFT + preference       LoRA fine-tune, before/after
                  quality filter    verify, QC gate         dataset                eval on hidden tests
```

| Stage | Repo | What it does, and where it stands |
| --- | --- | --- |
| Crawl | [**crawl-foundry**](https://github.com/muhib-karim/crawl-foundry) | Polite, resumable crawler: RFC 9309 robots.txt (tested), per-host pacing with `Crawl-delay` and `Retry-After`, SQLite frontier, gzipped WARC, licence and provenance per document. Real crawl of four Australian government sites: 3,085 documents, HTTP 200 rate 0.9994, against a 50k target still in progress. |
| Dedup and filter | [**dedup-scale**](https://github.com/muhib-karim/dedup-scale) | MinHash LSH near-dedup plus C4/Gopher-style quality rules on a local Ray cluster, over 119,944 FineWeb documents. Precision 0.94 and recall 0.9363 against an exact-Jaccard reference; 2.68x speedup on 3 workers. One shard on one machine so far. |
| Generate with a QC gate | [**agent-pipeline-qc**](https://github.com/muhib-karim/agent-pipeline-qc) | Generate, annotate, critique and verify with small local models, every stage typed with pydantic. A batch ships only if the verifier agrees with a 100-item gold set at 0.80 or above. The first verifier scored 0.520, so the gate refused the batch and the threshold was not lowered. |
| Dataset | [**countrykit-bangla**](https://github.com/muhib-karim/countrykit-bangla) | Bangla SFT and preference dataset (CC BY 4.0) from 600 original seed prompts, with per-item provenance, a rule verifier, the agent-pipeline-qc verifier and a contamination scan against Belebele (0 shared 8-grams). 270 SFT examples and 100 pairs so far, against targets of 1,000+ and 300+. |
| Fine-tune and evaluate | [**tiny-tune**](https://github.com/muhib-karim/tiny-tune) | LoRA fine-tune with a before/after eval through agent-eval-harness on 20 held-out tasks graded by hidden tests, plus a contamination check. The CPU smoke run is published, including the result that the tuned adapter did worse (6/20 vs 13/20); the T4 QLoRA run is scripted, not yet run. |

The stages are separate repos with their own inputs. Two links are wired today: countrykit-bangla runs the agent-pipeline-qc verifier, and tiny-tune is graded by agent-eval-harness. Training tiny-tune on the countrykit-bangla SFT slice is planned.

## Engineering focus

- **Data engineering for LLM training:** polite crawling, near-dedup and quality filtering, agentic generation behind a gold-set QC gate, contamination checks and LoRA fine-tuning with hidden-test evals.
- **AI evaluation:** repeatable tasks, withheld tests, pass@k and inspectable result records.
- **Verification & validation:** OpenAPI contracts, requirements traceability and clear failure reports.
- **Developer tooling:** LLM gateways, editor extensions and natural-language shells with safety guards.
- **Voice interfaces:** local speech-to-text on desktop and Android.

## How to review a project

Open its README, run the documented example, then read the tests and the CI run. CI badges show the checks each project configures; they don't replace testing in your own environment.
